# Focus Calendar 제품 원칙

## 1. 제품 정체성

Focus Calendar는 단순히 일정을 기록하는 캘린더가 아니다.
사용자의 시간, 일정, 계획이 현실과 어긋났을 때 다시 계산해주는 계획 조정 도구다.

핵심 문장:

> 계획을 세우는 앱이 아니라, 계획이 무너졌을 때 다시 계산해주는 앱.

이 앱은 사용자의 의지 부족을 탓하지 않는다.
계획과 실제 생활 사이의 차이를 감지하고, 지금 남은 시간 안에서 실행 가능한 형태로 다시 조정하는 것을 목표로 한다.

---

## 2. 해결하려는 핵심 문제

Focus Calendar가 줄이고자 하는 문제는 다음과 같다.

### 2.1 시간 부족 문제

사용 가능한 시간보다 해야 할 일이 많은 상태다.

예:
- 오늘 남은 시간은 2시간인데 할 일은 5시간 분량인 경우
- 활동 가능 시간이 끝났는데 미완료 작업이 남은 경우
- 기존 일정 사이 빈 시간이 너무 짧아 작업을 넣을 수 없는 경우

앱의 대응:
- 일부 작업을 미배치 상태로 남긴다.
- 미배치 이유를 설명한다.
- 마감일과 중요도를 기준으로 우선 배치한다.
- 사용자가 예상 소요 시간이나 활동 가능 시간을 조정할 수 있게 한다.

---

### 2.2 계획 재계산 문제

사용자는 계획을 세울 수는 있지만, 일정이 바뀐 뒤 다시 계산하는 데 약하다.

예:
- 갑자기 수업이나 약속이 추가되어 공부 시간이 줄어든 경우
- 오전 계획을 못 끝내 오후 계획까지 밀리는 경우
- 오늘 못 한 작업을 내일로 넘겼는데 우선순위를 다시 정하지 못하는 경우

앱의 대응:
- 현재 시각 이후 남은 시간만 기준으로 다시 배치한다.
- 이미 지난 시간대에 억지로 작업을 넣지 않는다.
- 미완료 작업을 단순 이월하지 않고 다시 평가한다.

---

### 2.3 마감 역산 문제

마감일은 알지만 언제부터 무엇을 해야 하는지 계산하지 못하는 문제다.

예:
- 시험일은 알지만 개념 학습, 문제풀이, 오답 정리, 최종 복습 일정을 나누지 못하는 경우
- 과제 마감은 알지만 자료 조사, 목차 작성, 본문 작성, 검토 시간을 분리하지 못하는 경우

앱의 대응:
- 마감일에서 거꾸로 필요한 단계를 나눈다.
- 오늘 해야 할 최소 행동을 제안한다.
- 시험이나 과제 전날에는 신규 작업보다 복습과 점검을 우선한다.

---

### 2.4 예상 소요 시간 오류 문제

사용자는 작업 시간을 자주 과소평가한다.

예:
- 보고서 작성 1시간 예상 → 실제 3시간 소요
- 문제풀이 60분 예상 → 오답 정리까지 120분 소요
- 발표자료 수정 30분 예상 → 대본 수정까지 90분 소요

앱의 대응:
- 예상 소요 시간과 실제 완료 시간을 기록한다.
- 유사 작업의 과거 기록을 바탕으로 시간을 보정한다.
- 입력 시간이 비현실적으로 짧으면 조정 제안을 제공한다.

---

### 2.5 미완료 누적 문제

완료하지 못한 작업이 계속 쌓여 사용자가 다음 행동을 정하기 어려운 상태다.

예:
- 어제 못 한 작업이 오늘 일정 위에 계속 쌓이는 경우
- 반복적으로 미뤄진 작업이 그대로 남아 있는 경우
- 중요도가 낮은 작업이 계속 오늘 일정에 섞이는 경우

앱의 대응:
- 미완료 작업을 다시 분류한다.
- 오늘 반드시 해야 할 작업과 미뤄도 되는 작업을 구분한다.
- 반복적으로 미뤄진 작업은 나누기, 축소하기, 보류하기를 제안한다.

---

### 2.6 집중 시간대 불일치 문제

어려운 작업이 사용자의 집중력이 낮은 시간에 배치되는 문제다.

예:
- 밤에 고난도 전공 문제풀이가 배치되는 경우
- 수업 직후 피곤한 시간에 보고서 본문 작성이 배치되는 경우
- 짧은 빈 시간에 긴 작업이 배치되는 경우

앱의 대응:
- 긴 작업과 어려운 작업은 충분한 빈 시간에 배치한다.
- 짧은 빈 시간에는 짧은 복습, 암기, 정리 작업을 추천한다.
- 사용자의 완료 기록이 쌓이면 집중 가능 시간대를 추정한다.

---

## 3. 기능 판단 기준

새 기능이나 변경은 다음 질문에 답해야 한다.

1. 사용자가 직접 다시 계산해야 하는 부담을 줄이는가?
2. 오늘 남은 시간 안에서 실행 가능한 행동을 제안하는가?
3. 계획이 어긋났을 때 다음 계획으로 조정하는가?
4. 배치 이유와 미배치 이유를 이해할 수 있는가?
5. 휴식과 여유 시간을 남기고 하루를 과도하게 채우지 않는가?
6. 사용자가 자동화 결과를 직접 수정할 수 있는가?
7. 기존 일정, Google Calendar 일정, 알림과 충돌하지 않는가?
8. 장기 목표와 마감 임박 작업 사이의 균형을 잡는가?
9. 실패 상태를 숨기지 않고 복구 행동을 제안하는가?
10. 모바일 화면에서 즉시 이해 가능한가?

위 질문에 명확히 답하지 못하는 기능은 범위를 줄이거나 도입을 미룬다.

---

## 4. 자동 배치 원칙

자동 배치는 사용자의 하루를 대신 통제하는 기능이 아니라, 실행 가능한 계획을 제안하는 기능이다.

원칙:
- 완료된 작업은 다시 배치하지 않는다.
- 이미 배치된 작업을 중복 생성하지 않는다.
- 기존 일정과 활동 가능 시간을 침범하지 않는다.
- Google Calendar 일정을 빈 시간으로 오판하지 않는다.
- 작업 사이에 현실적인 여유 시간을 둔다.
- 하루를 100% 채우지 않는다.
- 들어갈 수 없는 작업을 숨기지 않는다.
- 미배치 이유를 사용자에게 보여준다.
- 자동 배치 결과는 사용자가 수정할 수 있어야 한다.

---

## 5. 공부계획 기능 원칙

시험범위, 과목, 남은 시간 기반 기능은 Focus Calendar의 핵심 확장 방향이다.

이 기능은 단순 시험일 저장이 아니라, 마감일에서 거꾸로 공부 과정을 계산하는 기능이어야 한다.

고려 요소:
- 시험일까지 남은 날짜
- 시험범위
- 현재 진행률
- 과목 난이도
- 하루 공부 가능 시간
- 목표 수준
- 미완료 공부 블록
- 복습 필요 여부

기본 공부 단계:
1. 개념 학습
2. 문제풀이
3. 오답 정리
4. 암기 또는 서술형 정리
5. 최종 복습

원칙:
- 시험일까지 시간이 충분하면 개념 학습과 문제풀이를 넓게 배치한다.
- 시험일이 가까우면 오답 정리와 최종 복습 비중을 높인다.
- 진행률이 낮고 범위가 많으면 위험도를 높게 표시한다.
- 오늘 날짜의 공부 블록은 오늘 집중 블록과 연결될 수 있어야 한다.
- 완료된 공부 블록은 자동 배치 대상에서 제외한다.

## 6. UX 문구 원칙

문구는 사용자를 비난하지 않고, 현재 상태와 다음 행동을 안내해야 한다.

좋은 문구:
- “오늘 남은 시간이 부족해 일부 작업을 배치하지 못했습니다.”
- “예상 소요 시간이 남은 빈 시간보다 길어 내일로 이동했습니다.”
- “이 작업은 이전 기록보다 시간이 더 걸리는 경향이 있습니다.”
- “활동 가능 시간을 늘리거나 작업 시간을 조정해보세요.”
- “완료하지 않은 작업을 다음 가능한 날짜로 옮겼습니다.”
- “시험일까지 남은 시간에 비해 진행률이 낮아 위험도가 높습니다.”

피해야 할 문구:
- “계획을 지키지 못했습니다.”
- “오늘도 목표 달성에 실패했습니다.”
- “의지가 부족합니다.”
- “할 일을 또 미뤘습니다.”

---

## 7. 제품이 지향하지 않는 것

Focus Calendar는 다음 방향을 지향하지 않는다.

- 계획을 많이 입력하도록 압박하는 기능
- 죄책감이나 과도한 게임 보상으로 행동을 유도하는 기능
- 이유를 설명하지 않는 완전 자동화
- 사용자가 수정할 수 없는 고정된 시간표
- 하루 전체를 빈틈없이 채우는 일정표
- 단순 통계만 보여주고 다음 행동을 제안하지 않는 대시보드
- Google Calendar와 충돌하는 독립적 자동 배치
