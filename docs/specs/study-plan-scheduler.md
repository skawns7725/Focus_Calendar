# Study Plan Scheduler MVP 1차 설계

## 목표

시험 정보와 하루 공부 가능 시간을 입력하면 시험 전날까지 실행 가능한 날짜별 학습 블록을 만든다. 이번 단계는 계획 생성·조회·완료와 향후 자동 배치 연결 경계까지만 제공한다.

## 데이터 모델

### StudyPlan

- 시험명, 과목명, 시험일, 시험범위
- 현재 진행률(0~100), 난이도(1~3), 하루 공부 가능 시간(분)
- 소유자, 생성일, 수정일
- 여러 `StudyBlock`과 1:N 관계

### StudyBlock

- 소속 계획, 학습 날짜, 단계, 제목, 예상 시간, 순서
- 상태: `pending` 또는 `completed`
- 생성일, 수정일
- 계획 삭제 시 함께 삭제

두 모델은 기존 `Quest`, Google Calendar, 알림 모델과 관계를 맺지 않는다. 기존 데이터에는 영향을 주지 않는 신규 테이블만 추가한다.

## 계획 생성 로직

1. 오늘부터 시험 전날까지의 학습 가능 날짜를 구한다.
2. 하루 입력 시간의 80%만 계획 용량으로 사용해 휴식과 변동 여유를 남긴다.
3. 남은 진행량과 난이도를 반영해 총 권장 학습 시간을 계산한다.
4. 총 시간을 `개념학습 35% → 문제풀이 35% → 오답정리 20% → 최종복습 10%` 순서로 나눈다.
5. 각 단계는 하루 용량을 넘지 않는 날짜별 블록으로 분할한다.
6. 최종복습은 마지막 학습일에 놓고, 시간이 부족해도 생성된 블록과 부족 위험을 숨기지 않는다.

시험일이 오늘이거나 과거이면 생성 요청을 거절한다. 모든 블록은 사용자가 완료할 수 있으며 완료 상태는 즉시 저장한다.

## 위험도 계산

위험 점수는 아래 세 항목의 합이다.

- 남은 진행량: `100 - 진행률`
- 난이도 가중치: 쉬움 0, 보통 15, 어려움 30
- 날짜 압박: 3일 이하 30, 7일 이하 15, 그 외 0

점수 60 미만은 `낮음`, 60~99는 `보통`, 100 이상은 `높음`이다. UI에는 현재 상태와 이유를 함께 표시한다.

## 자동 배치 연결 인터페이스

도메인 함수가 미완료 `StudyBlock`을 다음 형태의 후보로 변환한다.

```ts
interface StudyBlockScheduleCandidate {
  sourceType: "study_block";
  sourceId: string;
  studyPlanId: string;
  title: string;
  date: string;
  expectedMinutes: number;
  category: "study";
  completed: false;
}
```

변환 함수는 지정 날짜의 `pending` 블록만 반환한다. 완료 블록은 후보에서 제외한다. 이번 MVP에서는 후보를 기존 `Quest`로 만들거나 기존 자동 배치 서비스에 주입하지 않는다.

## UI와 API

- 대시보드에 독립적인 `StudyPlanScheduler` 컴포넌트를 추가한다.
- 생성 폼과 계획 목록을 컴포넌트 내부에서 관리하되 API 호출은 `src/client/api.ts`에 둔다.
- 목록은 D-day, 위험도, 시험범위, 날짜별 단계와 완료 버튼을 표시한다.
- 저장 실패 시 입력 또는 완료 상태를 복구하고 다음 행동을 안내한다.
- 390px 화면에서는 단일 열로 바뀌고 가로 스크롤이 생기지 않게 한다.

## 제외 범위

- `Quest` 즉시 생성 또는 기존 자동 배치 로직 변경
- Google Calendar 동기화와 알림 변경
- 계획 수정·삭제·재계산 UI
- 통계 고도화, AI API, 대규모 UI 개편
- 배포와 커밋
